# WordPress 版 StackProof（テーマ一式）

Noimos 上で作ったサイト（AI・ソフトウェア比較サイト）の中身を、**ご自身の WordPress（toolstackindex.com）でそのまま運営できる形**に作り直したものです。テーマを有効化すると、ツール10件・カテゴリ・固定ページ・メニューまで自動で入ります。

構成しているファイル:

- `stackproof-theme/` … WordPress テーマ本体（これをアップロードします）
- `README.md` … この説明書

---

## 1. インストール（5分）

1. `stackproof-theme` フォルダを**フォルダごとZIP**にします（中身だけではなく、フォルダを右クリック → 圧縮）。
2. WordPress 管理画面 → **外観 → テーマ → 新規追加 → テーマのアップロード** → ZIPを選んで「今すぐインストール」→「有効化」。
   - 「リンク先のフォルダは既に存在します」と出てアップロードできない場合は、サーバーのファイルマネージャ（またはFTP）で `wp-content/themes/stackproof-theme/` を開き、**中身を新しいZIPの中身と入れ替えて**ください（フォルダ名は変えないでください）。入れ替えたあとも、管理画面を1回開けば下の点検は同じように走ります。
   - 反映されたかどうかは **外観 → テーマ** のバージョン表示で確認できます（**1.3.8** になっていれば最新です）。
3. 有効化した瞬間に、次が自動で作られます。
   - ツール10件（Notion / Zapier / Make / Jasper / Writesonic / Surfer SEO / Kit / GetResponse / ElevenLabs / Otter.ai）とカテゴリ5件
   - 固定ページ: ホーム / ブログ / このサイトについて / アフィリエイト開示 / プライバシーポリシー
   - メニュー2つ（ヘッダー用・フッター用）
   - フロントページ（ホーム）と投稿ページ（ブログ）の割り当て
   - サイトのタイトル（**設定 → 一般**）→「AI・SaaSツール比較ガイド｜ToolStack」。検索結果やタブに表示される名前です。別のタイトルにしたい場合は、あとから同じ画面で自由に変更できます（テーマ側から戻すことはありません）。
4. URLの形（パーマリンク）は、**サーバーが `/tools/` のようなURLを実際に返せるかを確かめてから**決めます。返せないサーバーでは、全ページが404にならないよう素のURL（`?post_type=sp_tool` 形式）で運用します（サイト内のリンク・メニューはすべて開きます）。判定の結果は管理画面のお知らせに表示されます。
5. 設置直後の点検で、次の4つも自動で確認・修復します。
   - 有効化が二重に走って増えてしまった重複ツール → ゴミ箱へ移動（管理画面から復元できます）
   - メニューのリンク → URLを固定せず、ページIDを参照する形に直す
   - **廃止した「ワークフロー・チートシート」の固定ページ** → ゴミ箱へ移動（消してはいません。「固定ページ → ゴミ箱」から復元できます）
   - ツール一覧のURLが**古い404のキャッシュに隠されていないか** → 隠されている場合は、管理画面に確認結果の表と直し方（サーバー側のキャッシュ削除）を表示します
6. サーバー設定やキャッシュを直したあとは、管理画面のお知らせの**「再チェック」**を押してください（お知らせを閉じてしまった場合も、管理画面を開けば再表示されます）。

## 2. 普段の使い方

| やりたいこと | 場所 |
|---|---|
| 記事を書く（ブログ一覧とトップの最新記事に反映） | 投稿 → 新規追加 |
| 成果リンクを貼る | ツール → ツールを編集 → 「成果リンク（アフィリエイトURL）」 |
| 外部リンクのクリック数を見る | 同じ編集画面の下部 |
| レビュー内容を直す | 同じ編集画面の「向いている人／メリット／注意点／評価」 |
| ツールを増やす | ツール → 新規追加（スラッグがそのまま `/tools/{スラッグ}/` と `/go/{スラッグ}` になります） |
| 法務ページを直す | 固定ページ（このサイトについて／開示／プライバシー） |
| お問い合わせの内容を見る | 管理画面の「リード」（あわせて管理者メールへ通知） |
| サイトのタイトル（検索結果やタブに出る名前）を変える | 設定 → 一般 → 「サイトのタイトル」 |
| ロゴ・サイトアイコン | 外観 → カスタマイズ |

提携先プログラムの一覧と申請の順番、記事の計画は `docs/affiliate-strategy.md` にまとめています（WordPress版での読み替え表つき）。

## 3. しくみ

- **発リンク**: サイト内の「◯◯を見る」は `/go/{スラッグ}` を経由し、クリックを数えてから302で転送します。転送先は「成果リンク」→ 空なら「ベンダーURL」。貼り替えは1か所で全ページに反映されます。
- **検索とカテゴリ絞り込み**: `/tools/` の比較表。JavaScriptが無い環境では全件を表示します。
- **404が出たときの見分け方**: `/tools/?sp_check=1` のように後ろに文字を付けて開いてみてください。**それで開けて `/tools/` だけ404**なら、サイトの設定は正常で、サーバーのページキャッシュに古い404が残っています（4章の手順で直ります）。逆に、文字を付けても404ならサイト側の問題です。管理画面の「再チェック」でも同じ判定が出ます。
- **AI検索向け**: テーマが `/llms.txt` を出力します（きれいなURLが使えないサーバーでは、同じ内容を `?sp_llms=1` で返します。サーバー設定を直すと `/llms.txt` が使えます）。サイトマップは WordPress 標準の `/wp-sitemap.xml`。
- **SEO**: ページタイトルは WordPress が自動で出します。説明文・OGP・構造化データはテーマからは出していないので、必要なら Yoast SEO や Rank Math を追加して設定してください。プラグイン側にも llms.txt の機能がある場合は、どちらか一方にしてください（テーマは `/llms.txt` を出力します）。
- **アクセス解析**: いまのNext.js版の独自アナリティクスはWordPress版には入っていません。必要ならプラグイン（Site Kit など）を追加してください。

## 4. まだ確認できていないこと（先にお読みください）

この作業環境には **PHP と WordPress 本体がない**ため、WordPress に入れたときの**画面表示の確認はこの環境ではできません**。その代わり、設置後に起きた問題を実際の設置先（toolstackindex.com）を外部から調べて確認し、次の3件を直しました（テーマ 1.2.0）。

- **トップ以外がすべて404になっていた** — サーバーが `/tools/` のようなURLを処理できていませんでした（メニューの「ツール」「チートシート」「ブログ」「このサイト」などが全滅）。テーマが設置時にURLの形を実際に確かめ、開ける形に自動で合わせるようにしました。結果は管理画面のお知らせに出ます。
- **同じツールが二重に入っていた** — 有効化が二重に走り、10件のツールが20件になっていました（トップの「20件すべてを見る」と一覧が食い違う原因）。重複分はゴミ箱へ移し（復元できます）、次回以降は増えないようにしました。
- **`/tools/` だけ404になっていた** — 外部から確かめたところ、WordPress 側は `/tools/` を正常に返していた（`/tools/?sp_check=…` は200）のに、訪問者が開くURLには 404 が保存されたまま配られていました（`/llms.txt` も同じ）。**テーマを入れる前に記録された古い404が、サーバーのページキャッシュに残っていた**ためです。原因はサイトの設定ではないので、テーマ側では次の2つを行います。
  - 1.2.0 の点検は「キャッシュを避けた確認」と「訪問者が開くURLそのもの」の両方を比べ、古い404が残っているときは**確認結果の表と直し方（サーバー側のキャッシュ削除）**を管理画面に出します。
  - 404の応答に「**キャッシュに残さない**」指示を付けるようにしました。今後は、一時的に404になったURLがキャッシュに固定されません。

あわせて、1.1.0 にあった危険な作りを直しました。1.1.0 は**1つのURLが404を返しただけ**でサイト全体のURLを素の形に切り替えており、そのURLに古い404が残っているだけの場合にかえって `/tools/` が本当に使えなくなる作りでした。1.2.0 は**すべての確認先が404のときだけ**切り替え、応答が確かめられないときは設定を変えません。あわせて、発リンク `/go/{スラッグ}` の取得を、設置先の環境で0件になっても拾えるようにしました（0件のときに提携先ではなくツール一覧へ飛んでいた原因です）。

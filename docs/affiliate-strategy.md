# StackProof 収益戦略（アフィリエイト）

作成: 2026-09-20 / 対象: StackProof（stackproof サブドメイン・英語・顔出しなし・テキスト中心）

この文書は「どの媒体で、何を売り、どの記事から送客するか」を決めるための計画です。
サイトに実装済みの事実（ページ構成・ツール10件・計測方法）に基づいて書いており、
実装と食い違う箇所はありません。報酬条件など**未確認の数字は「要確認」と明記**しています。

---

## 1. 結論：媒体は「検索 × 自前サイト × メール」の3層

| 層 | 媒体 | 役割 | 実装状況 |
|---|---|---|---|
| 集客 | オーガニック検索（Google / AI検索） | 比較検討中の読者を拾う主戦場 | SEO・GEO 有効。sitemap / llms.txt / JSON-LD 反映済み |
| 受け皿 | 自前サイトの比較ディレクトリと個別レビュー | 送客の最終地点。ここで初めて成果リンクを踏む | 10ツール / 5カテゴリ / `/tools`・`/tools/[slug]`・`/go/[slug]` |
| 再利用 | メールリスト（チートシート登録） | 唯一の「所有チャネル」。乗り換え時に送れる | `/cheat-sheet` の登録フォーム → DB保存済み |
| 配布 | Reddit・Substack などのテキスト面 | 初期の被リンクと読者獲得 | 記事を出すだけ。サイト側の作業は不要 |

**なぜこの組み合わせか。** このサイトは顔出し・音声なしの方針なので、YouTube やポッドキャストは使えません。
残る資産は「検索で見つかるテキスト」と「読者のメールアドレス」だけです。
比較記事は1本書けば数年にわたって検索から読者を運び、しかも読者は「今まさに選ぼうとしている」状態で来ます。
アフィリエイトは、この2つが揃ったときに最も効率よく回ります。

**やらない媒体。** YouTube・ポッドキャスト・音声・顔出し。方針に反するうえ、テキストの在庫を二重に作ることになります。

## 2. 取り扱う商品（提携プログラム）

サイトに登録済みの10ツールが、そのまま最初の商品リストです。
申請ルートは `src/lib/affiliates.ts` に記録済みの内容です（`program` フィールド）。

### 2-1. 申請の優先順位

| 優先 | ツール | カテゴリ | 申請ルート（記録済み） | 報酬タイプ（記録済み） |
|---|---|---|---|---|
| 1 | Kit | メール | PartnerStack | 継続（recurring） |
| 2 | Jasper | 文章・SEO | ベンダー直 | 継続（recurring） |
| 3 | Surfer SEO | 文章・SEO | ベンダー直 | 継続（recurring） |
| 4 | GetResponse | メール | PartnerStack | 要確認 |
| 5 | Notion | ワークスペース | ベンダー直 / Notion AI | 要確認 |
| 6 | Zapier | 自動化 | ベンダー直 | 要確認 |
| 7 | Make | 自動化 | ベンダー直 | 要確認 |
| 8 | Writesonic | 文章・SEO | ベンダー直 | 要確認 |
| 9 | Otter.ai | 音声・会議 | ベンダー直 | 要確認 |
| 10 | ElevenLabs | 音声・会議 | ベンダー直 | 要確認 |

**この順番にする理由。** 収益モデルは「15〜22%の継続報酬」（ワークスペースの目標設定より）です。
継続報酬のプログラムは、1件の成約が毎月積み上がるため、単発報酬より同じ手間で価値が数倍になります。
上位3件（Kit・Jasper・Surfer SEO）は**サイト側に継続報酬と記録済み**なので、まずここから申請します。
また Kit・GetResponse は PartnerStack 経由なので、**1つのアカウントで複数案件にまとめて応募**できます。

### 2-2. 申請前に必ず自分で確認する項目（この文書には書けない情報）

報酬率・Cookie期間・承認条件は各プログラムが一方的に変更でき、こちらでは検証できません。
承認された時点で、確認した実数を `src/lib/affiliates.ts` の `terms` フィールドに書き残してください
（このフィールドはサイトに表示されません。自分の記録用です）。

- [ ] 報酬率（%）と、継続か単発か
- [ ] Cookie 期間（何日間のクリックが成果になるか）
- [ ] 成果地点の定義（登録 / 有料転換 / 売上）
- [ ] 支払いサイトと最低支払額
- [ ] 条件変更の予告期間

### 2-3. 商品リストの拡張（2か月目以降）

現在は5カテゴリ・10ツールです。読者が次に探すのは以下の領域なので、**同じ手順で1ツールずつ追加**します
（`src/lib/tools.ts` に追記するだけで、ディレクトリ・比較表・チートシート・スタックに自動反映されます）。

- プロジェクト管理・タスク管理
- デザイン・資料作成
- 顧客管理（CRM）と請求
- 文字起こし以外の議事録系
- AI アシスタント全般

追加の判断基準は「**読者が実際に選び直すツールか**」です。
比較検討が発生しないツールは、レビューを書いても成果リンクが踏まれません。

## 3. 記事計画（最初の12本）

記事は3つの型で出します。どの型も最後は `/tools/[slug]` か `/go/[slug]` に着地させます。

- **比較型**（成約に最も近い。読者は財布を出しかけている）
- **課題解決型**（情報収集層。悩みから入って比較へ送る）
- **スタック型**（複数ツールをまとめて提案。1記事で複数プログラムに送客できる）

| # | 型 | 英語タイトル（サイトに掲載する言語） | 読まれる理由 | 送客先 |
|---|---|---|---|---|
| 1 | 比較 | Zapier vs Make: which automation tool to start with | 「どちらを契約すべきか」で検索される定番の分岐点 | `/go/zapier`・`/go/make` |
| 2 | 比較 | Kit vs GetResponse: newsletter-first or funnel-first | メールツールの乗り換え検討層 | `/go/kit`・`/go/getresponse` |
| 3 | 比較 | Jasper vs Writesonic for a two-person content team | 少人数チームの導入判断 | `/go/jasper`・`/go/writesonic` |
| 4 | 比較 | What Surfer's content score actually measures | 既存ページの順位を上げたい層 | `/go/surfer-seo` |
| 5 | 比較 | Otter.ai for people who take the same call every week | 商談・面談の議事録課題 | `/go/otter-ai` |
| 6 | 課題 | Automating client onboarding without writing code | 手作業のオンボーディングに困っている層 | `/go/zapier` → `/go/make` |
| 7 | 課題 | Where to keep client call notes so you can find them in six months | 情報が散らかる課題 | `/go/otter-ai` → `/go/notion` |
| 8 | 課題 | Turning a written library into audio: consent rules first | 音声化を検討する制作側 | `/go/elevenlabs` |
| 9 | 課題 | The four tools a one-person consultancy actually pays for | 開業直後の初期選定 | `/#stacks` |
| 10 | スタック | The solo consultant stack, explained | 提案済みスタックの解説 | `/go/notion`・`/go/otter-ai`・`/go/kit` |
| 11 | スタック | The content-led startup stack: draft, check, send | 週次の運用ループを回したい層 | `/go/writesonic`・`/go/surfer-seo`・`/go/kit` |
| 12 | スタック | The lean operations stack for teams with no one to wire things up | 既存ツールの接続課題 | `/go/zapier`・`/go/make`・`/go/notion` |

**執筆ルール（サイトの方針と一致させる）。**
- 見出しに「おすすめ」「最強」を使わない。**どの読者が使うべきで、どの読者が飛ばすべきか**を書く
- 価格・数値・受賞歴は、**ベンダーの公式ページを実際に読んだものだけ**書く（推測で書かない）
- 記事内のリンクは `/go/[slug]` を通す。クリックは自動で計測される
- 記事末に必ず開示文（アフィリエイトリンクであること）を置く

## 4. 実行順序（90日）

| 期間 | やること | 完了の目安 |
|---|---|---|
| 1〜2週目 | 継続報酬の3プログラム（Kit・Jasper・Surfer SEO）に申請。比較記事 #1・#2 を公開 | 申請3件・記事2本 |
| 3〜4週目 | 承認されたプログラムのリンクを `src/lib/affiliates.ts` に反映。記事 #3・#4 を公開 | 承認1件以上・記事4本 |
| 5〜8週目 | 週1本のペースで #5〜#10。Reddit と Substack で各記事を1回だけ紹介 | 記事10本 |
| 9〜12週目 | 検索表示回数を見て、伸びている記事を加筆。#11・#12 を公開。ツールを3件追加 | 記事12本・ツール13件 |

**承認が下りるまでの間も止めないこと。** 承認前にできる作業（記事・ディレクトリ拡充）が収益の9割を決めます。
リンクは未承認の間もベンダー公式ページに飛ぶので、読者に迷惑はかかりません。

## 5. 計測と目標

### 5-1. 数字の取り方（すべて設定済み）

| 見たい数字 | どこで見るか |
|---|---|
| 訪問数・ページ別の閲覧 | Manage → Analytics（自前の計測。設定不要） |
| **発リンクのクリック数** | Manage → Analytics の `$cta_click`（成果リンクのクリックを自動計測） |
| どの記事が読まれたか | 同画面のページ別レポート ＋ 滞在・スクロール率 |
| メール登録者 | Manage → Leads（チートシート登録フォームの保存先） |
| 実際の成約 | 各アフィリエイト管理画面（サイト側では分からない） |

### 5-2. 目標（ワークスペースの目標設定に合わせた3段階）

| 段階 | 目標 |
|---|---|
| 第1 | 提携プログラム3件に承認される／公開ディレクトリが共有可能な状態になる |
| 第2 | ディレクトリ訪問50以上／発リンククリック10以上 |
| 第3 | メール登録5件以上 **または** 発リンククリック25以上（広告費ゼロで） |

第3段階まで到達したら、その数字を持って次の判断（ツール追加・有料化・広告）に進みます。

## 6. サイト側の作業（どこを触るか）

| やりたいこと | 触るファイル | 備考 |
|---|---|---|
| 成果リンクの貼り替え | `src/lib/affiliates.ts` | **1か所だけ**。全ページに反映される |
| ツールの追加 | `src/lib/tools.ts` | 追記だけで一覧・比較表・チートシートに反映 |
| スタックの追加 | `src/lib/tools.ts` の `STACKS` | ホームのスタック欄に反映 |
| 記事の執筆・公開 | 管理画面の記事エディタ（`/blog` に配信） | コードは触らない |
| メール送信の有効化 | Manage → Email | **現在は未有効**。有効化すると登録者への通知が送れる |

**現状で未設定のもの。** メール送信（Manage → Email）が未有効のため、
今はリスト登録者にメールを送れません。登録の受け皿（DB保存）は動いています。
決済（Stripe）は未接続ですが、この収益モデルでは使いません。

## 7. リスクと対策

| リスク（目標設定で挙げられているもの） | 対策 |
|---|---|
| 検索と掲示板からの流入が安定するまで時間がかかる | 記事は「比較型」から出す。検索意図が明確な語は立ち上がりが速い |
| 報酬率・Cookie期間をベンダーが一方的に変更できる | 特定1社に依存しない。**最低3プログラム**を維持し、条件は承認時に記録する |
| 顔出しなしのテキストサイトはデータ精度で信頼を作る必要がある | 数値はベンダー公式ページで確認したものだけ書く。各レビューに**執筆日を明記**（実装済み） |
| ステマ規制・景表法への抵触 | 全ページに開示ページへのリンクを設置済み。`/disclosure` で方針を明示済み |

## 8. やらないこと

- 顔出し・音声・動画（ブランド方針）
- 有料掲載枠・スポンサード順位（`/about` で「掲載順は売り物ではない」と明言済み）
- 根拠のない順位・星評価・受賞歴（読者の信頼を一度で失う）
- 価格の推測記載（確認していない数字は書かない）
- 1記事に成果リンクを詰め込むこと（読者が離れ、クリック率が落ちる）

## 10. WordPress版（toolstackindex.com）での読み替え

同じサイトを WordPress で運営する場合（`wordpress/stackproof-theme/`）、上の手順とファイルは次の場所に変わります。

| やりたいこと | Next.js版（このリポジトリ） | WordPress版 |
|---|---|---|
| 成果リンクの貼り替え | `src/lib/affiliates.ts`（1か所） | ツール → 該当ツール → 「成果リンク（アフィリエイトURL）」 |
| ツールの追加 | `src/lib/tools.ts` | ツール → 新規追加（スラッグがそのまま `/tools/{スラッグ}/` と `/go/{スラッグ}` になります） |
| チートシートの7行 | 辞書ファイル（`src/lib/dictionaries/ja.ts`） | テーマの `inc/data.php` |
| 記事の執筆・公開 | 管理画面の記事エディタ（`/blog` に配信） | 投稿 → 新規追加（同じく `/blog` に表示） |
| 発リンクのクリック数 | Manage → Analytics の `$cta_click` | ツール編集画面の下部（`/go/{slug}` の302転送時に記録） |
| メール登録・お問い合わせ | Manage → Leads | 管理画面の「リード」 |
| チートシートの印刷 | ブラウザの印刷 | 同じ（「印刷 / PDF保存」ボタン） |

インストール手順と運用の詳細は `wordpress/README.md` にあります。
